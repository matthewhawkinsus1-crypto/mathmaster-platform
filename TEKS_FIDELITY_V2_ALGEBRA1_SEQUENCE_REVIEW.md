# Algebra I TEKS Fidelity V2 — Sequence Strand Review

Scope: A.12C and A.12D.

## A.12C — Recursive sequences
Preliminary verdict: ENHANCE.

### What is already strong
- Includes recursion, sequence-type recognition, error analysis, and contextual application.
- Uses more than one task type and more than one DOK level.
- Includes explicit misconception feedback about confusing additive and multiplicative patterns.

### What is missing
The current family set treats the standard as a collection of question types rather than a connected representation model. Students should experience the term number as the input/domain and the term value as the output/range before recursion is isolated as notation.

### Repair target
Preserve strong existing families but add/replace enough content so a session can deliberately include:
1. build a term-number/value table from a sequence or rule;
2. identify domain as discrete positive term numbers appropriate to the situation;
3. plot ordered pairs (n, f(n)) on a coordinate plane as discrete points;
4. connect the plotted pattern/table to a recursive rule;
5. analyze a misconception or application at higher DOK.

The graph must be discrete. Do not connect sequence points with a continuous line unless a separate question explicitly asks why doing so would misrepresent the domain.

## A.12D — Explicit formulas for sequences
Preliminary verdict: ENHANCE.

### What is already strong
- Arithmetic and geometric explicit forms are represented.
- Includes reverse-position reasoning and error analysis.
- Includes table-to-equation translation.

### What is missing
A.12D should serve as the natural continuation of A.12C rather than an isolated formula standard. Students should move from a table/graph they understand to the explicit rule and use the explicit rule to predict distant terms efficiently.

### Repair target
Preserve valid explicit-formula families but ensure the family set supports:
1. table -> explicit arithmetic formula;
2. table -> explicit geometric formula;
3. graph/discrete ordered pairs -> explicit formula;
4. compare recursive vs explicit rule and decide which is more efficient for a distant term;
5. reverse reasoning: solve for term number from a target value.

## Cross-standard progression
The Path selector should eventually be able to recognize and sequence these conceptual states:
- recognize pattern structure;
- establish n as input/domain;
- create term table;
- graph discrete ordered pairs;
- write/use recursive rule;
- write/use explicit rule;
- compare representations and solve applications.

This progression should inform the later My Path UX redesign, but content should be repaired before the UI promises it.
