# Close the open findings from PRs #407 and #408

_The full report of the #407/#408 cleanup pull request. Its description is a condensed copy. Every suite in **D** and **E** ran on `65c9dc40`._

This PR works through everything PRs #407 and #408 left open: their "Discovered Issues Not Fixed", "Further Opportunities", technical-debt and known-limits lists, the #407 deep dive (`docs/qa/platform-engineering-deep-dive-2026-10-01.md`), the deferred rows of the platform quirks audit, and the case review's design, status and verification notes. Each item was re-investigated from the code. Each now has one disposition, with a commit and a test where something changed. Defects found along the way are listed separately in **B**.

**Merged with `main` at 2189ceeb** (#412 server-authoritative grading, #413 Live Challenge and Rewards hardening; merge 0b9a90c7) **and again at b45dc60b** (#414 rich-tool question families and automatic question values; merge 420467de). #412 moved grading into shared graders that the browser's Check, ingestion, the deadline finalizer, Recovery and the Response Inspector all run. Every grading rule this PR adds or changes was moved into those graders, so the device and the server apply it alike (`docs/architecture/SERVER_GRADING_COVERAGE.md` §3.5 lists each one). The fraction rules (item 12, B-57) are the exception by design: the server declares fractions client-graded, so the shared fraction grader runs in the browser and ingestion bounds its verdict. Two outcomes changed in the move. A misplaced point now costs a relation plot its whole stage, because #412 grades every graph stage all or nothing (B-8). The old I-10 is closed: #412's graph-end markers store no verdict, and the grader judges the drop in graph units. The merges and their verification also turned up ten more defects, B-49 to B-58. #414 merged with two conflicts, an import list and a browser test's header comment, and nothing in its own code changes here. Its arrival needed two fixes in this branch's fraction rules (B-56, B-57).

**Nothing was deployed.** The release needs every default-codebase function (provenance labels), the `path-admin` codebase, Firestore rules and Hosting, then two admin steps. See **G**.

**62 findings from #407 and #408, each with exactly one disposition:** 43 FIXED · 1 ALREADY FIXED (verified at #407) · 11 INTENTIONAL (verified and documented) · 2 NOT REPRODUCIBLE (with the evidence) · 1 CANNOT BE RECONSTRUCTED (the data was never recorded) · 4 OUT OF SCOPE (three new features and one architecture change). **58 more defects found and fixed on the way (B):** 11 P0 (grading or lost work), 17 P1, 19 P2, 11 P3. Section **I** lists the 11 things this PR deliberately leaves, each with its reason: owner or product decisions, an operator step, work that needs its own PR, and a race in `main`'s Live Challenge QA. Every test suite and browser journey passes on the final head (**D**, **E**), except that QA's `reconnect` console check, which fails intermittently on `main` too (I-11).

## C. What changes

### For students
- **DOL, quiz and test graphs give nothing away.** No point check, no reflected-point check, no "Graph correct", no snapping to the true function, no pulsing graph ends or pulled markers, no hints of any kind. The curve goes through the student's own points and is graded on submission exactly as practice grades it. Practice, Warm-Up and Classwork behave as before.
- **A card that says "x = −1" places at x = −1**, wherever the student taps. Only the height is theirs. A point whose x they must find is never held.
- **Correct relation plots count**, including a relation with two points at the same x.
- **Fraction questions are graded on the answer their author wrote.** Any listed form counts, and the math line under the prompt shows.
- **Every student's version of a templated fraction question is held to one rule**: lowest terms, or the version's own key. "Simplify 4/8." no longer accepts 4/8 from a student whose key came out 2/4 (B-57).
- **A fraction that ends a sentence keeps the full stop after it**, not under the fraction bar (B-58).
- **Math fields look right in production.** Fractions, radicals and exponents use the math fonts again.
- **Scratchpad pages save** (multi-page scratchpads failed to save on graded work).
- **In practice, every hint a student opens is recorded**, one at a time, and the footnote no longer promises hints where there are none.
- **Nothing before Submit gives away a DOL, quiz or test anywhere else either.** The systems workspace (2×2 and 3×3 checks, 3D captions, "Reveal the solution point"), student-built inequalities, intercepts, the relation solver's graph, the constraint builder's checklist and the modeling lab's result now record the work and say nothing until release.
- **Nothing is chosen for you.** A tool that asks you to decide something (how many solutions, which direction, whether it is a factor) starts on "Choose…"; leaving it there is not an answer, and choosing what a tool used to pre-select counts, at a deadline too (B-52).
- **Changing checked work means checking it again**: the graph or arrows on screen are the ones graded.
- **What an attempt cost is shown beside the tool's verdict**, on screen and announced once ("Not quite. You have 2 attempts remaining"). The "Focus on" line names only parts the question asked, in words a student reads.
- **Work that comes back on another Chromebook does not move the cursor.** If the student has already clicked into a box when their saved work arrives, the cursor stays in that box, and what they type goes there (B-55).
- **One Undo for the whole representations board**; typing a fraction is one Undo step; Undo keeps keyboard focus.
- **Phones:** a phone on its side gives the step 235–265 px; the identity bar is one line; nothing hides under Enlarge; a typed table stage scrolls above the number keypad; taps land where they are made on a letterboxed plane.
- **Sign-in is faster on slow Chromebooks.** The sign-in screen appears about 0.4 s sooner on a 4x-throttled CPU than on `main` (1969 → 1528 ms), because the math library builds only what a student uses, when they first use it.
- **Smaller:** one help fold ("How to do this"); long verdicts are cards, not lozenges; Expression Meaning reopens on the unfinished row; "Submit my regression"; "steps", not "workflow".

### For teachers
- **Extensions stay private.** A classmate's device no longer receives a student's absence dates or who granted an extension. The case review shows one entry per grant.
- **Duplicate works** for assignments that have extensions. Library releases no longer carry a class's closures, unlocks or attempt grants into the next class.
- **Deleting a student** removes their entries from shared assignments.
- **Administration → Classes → Student privacy on assignments**: the one-time move and the class-scoped switch (runbook in `docs/DEPLOY_FROM_CLOUD_SHELL.md`, Block 5).
- **Case review:** next steps survive closing the review and a reload in that tab (never saved to MathMaster; cleared at sign-out), the review is usable on a phone, and a tool's misconception code reaches it once a tool emits one.
- **A fraction question can be a Question Family template.** Create checks the keys it generates, not the template, and Pre-Flight names a generated version whose key cannot be graded (B-56).
- **Scores count only what a question asks.** A 2×2 matrix question no longer gives a third of the credit (half, with no unique solution) for a technology step it does not have (B-50). A 3×3 interpretation submitted half right earns half (B-24).
- **The gradebook's part list shows only the parts a question asked**, by name (no more red "fog" on an inverse-only question).

### Technical
- `functions/shared/assignmentPrivacy.mjs` is the one definition of what may sit on a shared assignment, what a copy strips, and what deletion removes. The rules, both callables, Duplicate, the content release and the case review all read it.
- `ToolRuntimeContext` carries the activity policy (`showImmediateFeedback`, `hintsAllowed`, `onHintUsed`, `questionTerminal`), and QuestionEngine mounts composed questions inside the same provider as registry tools.
- `functions/shared/fractionAnswer.mjs`: one reader of written numbers and question shapes, used by generation, grading, display, validation, variability and support. A key drawn from a template (a version's `familyInstance`, or `answerKeyDrawn`, which `src/problemGenerator.js` sets where it fills a Path-style template) is held to lowest terms or its own form (B-57). `splitProseFractionRuns` (`src/components/common/mathSegments.js`) hands a denominator's trailing full stop back to the prose (B-58); `stackDivisions`, which grading uses, is unchanged.
- Release provenance: a predeploy stamp, labels on every function, `platformBuildInfo`, a verify step and `--whats-live`.
- `src/platform/math/mathliveRuntime.js` is the only place the editor is loaded. mathjs is built in two places, each on first use: `src/platform/math/mathjs.js` (one `create(all)` instance) and #412's hardened `functions/shared/algebra/safeMath.mjs`.
- After the merge, every grading rule here lives in #412's shared graders (`functions/shared/serverGrading/**`, tool math in `functions/shared/toolMath/**` behind `export *` shims), with browser/server parity suites in `tests/tools/*SharedGrading.test.mjs`. Work carries two new optional flags: `outcomesWithheld` (composed and Systems work on a DOL, quiz or test) and `choicesOpenUnanswered` (`OWN_CHOICES`). Both are documented in `docs/architecture/adding-server-grading-to-a-tool.md`.
- `submissionIngestion.mjs` `withAuthoritativeActivityRole`: a submission is judged under its question's role (B-51).
- `region()` in `tests/platform/helpers/sourceContract.mjs` fails on a missing end marker (B-53).
- Test infrastructure: one-resolution module swaps, a warm gate server, failure classification for missing `functions/` installs, and two read-only CI workflows. The student-runtime browser gates also run when `functions/shared/**` changes, since the student runtime grades with it, and they include the new `fractionTemplateGrading` gate.
- `toolSubmissionParts.js`: what a tool's Check records. `attemptOutcomeSlots.js` / `AttemptOutcome`: where the outcome goes. `useFocusSafeDisabled.js`: a disabled button keeps focus. `useToolSubmission` now signals `ATTEMPT_WITHDRAWN`.
- Outbox: a per-student retired tally and an acknowledged-report record, both in the existing `deviceIdentity` store; `deviceReportDedupe.js`.
- Systems workspace and solvers: `inequalityBuildPolicy.js`, `algebraicOutcomeModel` gates, `spatialFeedback`, the `withSolverRuntime` wrapper in QuestionEngine.
- Teacher harness fakes apply query constraints and reject unknown callables.

### Protected lanes: what was touched, and how

- **Live Challenge and Challenge modes:** no Live Challenge file edited. Rounds mount QuestionEngine with `activityRole="practice"`, so the stricter outcome and hint policy does not change them. `origin/main` with #410 (host console, projector, pacing) is merged in: `functions/index.js` merged cleanly, every suite passes on the merged tree, and #410's `src/platform/liveChallenge/` hooks pass the new `exhaustive-deps` error rule unchanged. Rounds grade tool questions with the shared Path tool grader (`pathToolContracts.mjs`), so the two grader fixes apply to them too: the relation tool's "is it a function?" answer is graded as the tool grades it (B-30; rounds graded it backwards), and an `algebra` workspace's equation is accepted (B-31). Answers in the old shapes (yes / no, `value`) are still read. Rounds key QuestionEngine per question instance, so its reset no longer runs on mount (B-44): a response module's first report is kept instead of wiped and sent again; what a round receives is the same. #413 (Live Challenge and Rewards hardening) is merged as well, with no conflict in any Live Challenge or Rewards file. The Live Challenge, repeated-match and Graph Feature Rush browser suites pass on the merged head, and so does every scenario of the shell QA but one console check in `reconnect`, a race in that QA which `main` shows too (**E**, I-11). B-49 makes rounds credit "is it a function?" only for the definition, as the tool does.
- **Drafts, shared by every lane (B-45 to B-47):** values store and restore on the same device exactly as before. Live Challenge rounds keep local-only drafts, which are never sent to the server, so only their internal timestamps change. Section recovery's drafts get the same protection as every assignment draft: opening never overwrites work.
- **Rewards:** not touched. The rewards store imports `normalizeQuestionRecord` from `attemptPolicy.mjs`, which this PR does not change (only `recordQuestionAttempt` gained the optional code).
- **IEP / accommodations / support evidence:** not touched. The support-summary listener (item 8) is left as designed. The case review (#408) builds on #401's support records, which it reads unchanged.
- **Make-up Warm-Up / DOL and recovery:** no make-up or recovery logic changed. Ingestion fills a missing activity role from the question (B-51). The student app always sends the question's role, so make-up work is judged exactly as before. Shared infrastructure touches them in three places, each additive or protective. Their per-class runtime state (closures, early unlocks, moved dates, attempt grants, the recovery audit) is no longer copied into Duplicate or library content releases (B-3). Permanent deletion replaces a deleted student's id in the recovery audit with the deletion receipt (B-4). Fraction drills still draw exactly the numbers they always drew, pinned for 7 generation keys, so generated make-up versions do not change. Section recovery grades through the shared server grader (`questionFamilyGrading.mjs` → `ordinaryResponseGrading.mjs`), so there too a `fraction` question with an authored answer is graded on that answer, and a drill exactly as before.
- **Question families / generation:** only the fraction shapes (item 12) and, for B-57, one additive mark: where assignment delivery fills a Path-style template, a fraction version carries `answerKeyDrawn` (in memory only; nothing else generated changes). Seat writes now reach only their class's devices (item 32). #414 (assignment-local families, question values) is merged with none of its code changed. The two fixes it needed are in this branch's fraction rules (B-56, B-57), and its suites pass on the merged tree, including its `family` journey on the representations board.

## F. Data safety

- **Grades.** No migration recomputes a recorded grade. Each grading fix (fractions, relation plots, same-x cards, DOL curves, the Path relation and algebra graders) applies to attempts made after the release. Recorded attempts keep their scores, so nothing passed back to Classroom changes on its own. A teacher who wants to credit an earlier correct relation plot or authored-fraction answer uses the existing audited grade override. Live re-marking (a teacher's question correction) now never lowers a part or a total.
- **Attempts.** Attempt counting is unchanged everywhere. Where outcomes are withheld there is no check left to spend or probe.
- **Drafts and saved work.** Draft formats are unchanged. Saved point placements are restored as saved: a held x applies only to placements made after the release. The sketch's graph-coordinate copy stays out of the response key, so a restored sketch is not "changed" work. Scratchpads: graded saves work again (B-1). Only Practice and preview scratchpads are held in memory, and the LRU drops the least recent beyond 8 MiB, never the open one (about 150 full handwritten pages).
- **Deadlines.** `lateDueAt` is never rewritten. The move keeps `{dateKey, grantedAt}` on the shared document, because attendance reconciliation reads `dateKey` to avoid granting twice.
- **Existing assignments and Firestore data.** `migrateAssignmentPrivacy` is a root-admin, dry-run-by-default, idempotent and audited callable. It copies each extension verbatim, unknown keys included, into `grades/{sid}/attendanceExtensionGrants/legacy__{aid}` (`legacyExtension`) in the same transaction that reduces the shared copy. It pages past 200 assignments, and a second run changes nothing (emulator test). New: the `attendanceExtensionGrants` subcollection and the `platformFlags/assignmentReadScope` document. Nothing is deleted.
- **Student visibility.** The class query uses the same audience rule students were already filtered by (`assignmentIsForStudent`: `assignedClassIds` contains the class). Assignments with work from an earlier class are still read by id, so mastery, grade repair and resume see what they saw before.
- **Outbox data on devices:** retired rows are never pruned, moved or rewritten. A device with old rows and no tally builds it once, from those rows. A device that cannot read its tally reports zero retired rows, as the old code did when its read failed (79be2b0b).
- **Tool drafts:** two now store less. A pending balance move keeps only what the student did (B-40), and a pending inequality-symbol step no longer keeps its expected symbols (B-42); both still read their older shape. A choice that used to open preselected opens on "Choose…" only in new work: a saved draft restores exactly the choice it holds (B-38).
- **Draft records:** server draft entries saved by the new code carry `savedAtIsEdit: true`, and the device's envelope gains `touchedAt` (expiry runs from it, so drafts live exactly as long as before). Older builds ignore both, and the schema version stays 1 (the rules require it). No migration: an unmarked entry is treated as an older build's. Practice is merged per question on the server, keeping the record with more progress.
- **Case review next steps:** kept only in that tab's session storage, keyed by the signed-in account, at most 10,000 characters, cleared at sign-out and never written to Firestore (e0f5bb74).
- **Recorded parts:** only new attempts of Inverse & Composition and Data Modeling questions record fewer parts (only those asked). Stored records keep their parts (81587fe6).
- **Grading changes from the merge apply to new attempts only:** a 2×2 matrix's technology part (B-50), half credit per judgment on a 3×3 interpretation and its judged reading (B-24), all-or-nothing relation plot stages (B-8). Recorded attempts keep their scores. #412 already graded every new attempt on the server from its raw work.
- **Fraction keys drawn from a template (B-57)** follow one rule in attempts made after the release; recorded attempts keep their scores. The `answerKeyDrawn` mark exists only on the question in memory and is never stored. #414, merged in, rewrites no stored assignment either (`docs/architecture/question-values.md` §8). B-58 changes only how a prompt is drawn.
- **Late restores (B-55)** change only where the cursor goes when saved work arrives after a question opened. Drafts, their format and their precedence are unchanged.
- **Ingestion (B-51)** changes only envelopes that carry no activity role: they are judged under their question's role. Nothing stored is rewritten.
- **New optional work fields:** `outcomesWithheld` (composed and Systems work where outcomes are withheld) and `choicesOpenUnanswered` (Data Modeling, the Polynomial Workshop). Work saved without them, by older clients, is graded as it always was.
- **Systems 3×3 responses** now carry the student's chosen kind and a two-part attempt in practice as well. Practice grades are unchanged, because a practice submission there is right by construction (ec2c1fe0).

## H. Rollback

Every step is independent and needs no data repair. The release tool's report (`release-reports/`) records what shipped and prints its own rollback commands.

1. **Class-scoped assignment lists:** Administration → Classes → **Turn off**. Takes effect at once, with no deploy. Do this first if anything about student assignment lists looks wrong.
2. **Hosting:** roll back to the previous release (Firebase console → Hosting → release history), or `npm run deploy:hosting` from the previous commit. The previous client works under the new rules while the switch is off.
3. **Cloud Functions:** from a checkout of the previous `main` commit, `node scripts/release-firebase.mjs --execute --only functions,path-admin`. The three new callables (`migrateAssignmentPrivacy`, `setAssignmentReadScope`, `platformBuildInfo`) are additive and can stay. A rolled-back `applyStudentAttendanceExtension` writes new grants' details to the shared document again, which is the privacy exposure this PR removes, but no data is lost.
4. **Firestore rules:** with the switch off, `firebase deploy --only firestore:rules` from the previous commit. The old `assignments` rule allows everything the new one does with the switch off.
5. **The fraction rules (item 12, B-56, B-57)** run in the browser, so they roll back with step 2. **The merge's grading rules** live in the shared graders, which the browser and the Cloud Functions both run, so they roll back with steps 2 and 3. Rolling back only Hosting leaves new attempts graded by the new server: the two agree again once both are rolled back. A response from a newer client than the server is kept and waits, never lost (`response-contract-newer-than-server`).
6. **Data needs nothing undone.**
   - The privacy move keeps every deadline and the reconciliation stub on the assignment, and the verbatim originals in `attendanceExtensionGrants` (Block 5). Only the earlier case review's "N class meetings" note reads less after a code rollback.
   - The outbox tally and the report acknowledgement are extra keys in an existing IndexedDB store, and the previous release ignores them. If a previous-release tab retires rows without counting them, this release's per-page check rebuilds the tally.
   - No grade, attempt, draft or deadline was rewritten.
   - A rolled-back client ignores `savedAtIsEdit` and `touchedAt`, and draft timing returns to the old behaviour: opening a question re-dates its draft (B-46) and an opening replaces a whole practice tracker (B-47).

## I. Remaining items, with concrete reasons

**I-1. The App shell split (item 16).** Item 7 took mathjs's cost out of sign-in (404 → 53 ms of main thread at 4x CPU) without it. What the split would still take out of a student's first load is mathjs's 641 KB download, cached `immutable` after the first visit, and the teacher-only modules (`assignmentV5PreflightModel` 210 KB, `pathBankSimulationService`, `SupportProfileEditor`, …). That means moving the Student and Teacher screens of an 11.9k-line component behind lazy boundaries, which touches every student and teacher flow at once, in a file every concurrent branch edits (#410 has just landed in it). It needs its own PR, planned against the open branches and run through the same browser suites. Meanwhile `initialBundleBoundary.test.mjs` keeps the first load from growing, and now also keeps mathjs's prebuilt instance out of it.

**I-2. The release tool's first run against production (item 23).** It needs production credentials and an operator, and nothing deploys from a branch. This PR's release is that first run: the plan in **G**, then `--execute`. If the functions do not report the merged commit, the verify step stops the release before path-admin, rules and Hosting.

**I-3. Grades recorded under the old graders are not re-graded (owner's decision).** Relation-plot stages (B-8), relations with two points at the same x (B-12), authored-answer fraction questions (item 12, B-17) and, in My Math Path and Live Challenge, the relation tool's "is it a function?" part (B-30, B-49) were graded wrong before this release, and 2×2 matrix questions gave a technology part they do not have (B-50). Re-grading would change recorded scores and Classroom passback without a teacher, so this PR does not. The audited grade override is available per student. The platform's one automatic re-grade (`repairQuestionRecordForCurrentGrader`, graph-analysis domain and range) only ever raises credit and was itself a product decision; extending it to these graders, or a bulk re-grade, is the same kind of decision and would be a separate, dry-run-first admin operation.

**I-4. What a classmate can still see on a shared assignment.** After this PR a student's device receives only its own class's assignments, and an extension there carries no reasons (no absence dates, meeting counts or granting teacher). It still carries each classmate's deadline entry (`lateDueAt` and `{dateKey, grantedAt}`), excused/reopened state and DOL attempt grants keyed by student id. Removing those means moving `studentOverrides` off the shared document (the deep dive's step 1). Every deadline reader (client lifecycle, ingestion, checkpoint finalizers) and the make-up DOL/recovery state, which is protected, would have to move with it, as a coordinated multi-release migration.

**I-5. `exhaustive-deps` outside `src/platform/` (remainder of item 13).** 158 warnings remain (main: 169): `App.jsx` 21, `InteractiveGraphWorkspace.jsx` 17 (none new), and the rest across tools. Making them errors means reviewing each site, many in `App.jsx` and in protected-lane screens, so they stay warnings. They are an error where the fan-out bugs were.

**I-6. No classroom tool emits a misconception code yet (CR-4).** The pass-through is complete end to end, but choosing codes for a tool's wrong answers (graphing2's construction `category` is not one) is a pedagogy decision for the curriculum owner, and a question-level code would need a new field on the question record. The case review says "Error pattern not determinable from stored evidence" until a tool emits one.

**I-7. PQ-023 step 3, moving the help fold below the first panel.** The audit made it conditional on a pedagogy check (does the student need the steps before they start?). Steps 1–2 are done.

**I-8. Left as designed, with reasons (DOL audit):**
- Step-algebra per-move validity and its "N% partial credit so far" are the solver's interaction model: each move must be valid to continue, and no answer is revealed. Removing them would replace a rich workflow.
- The "cancellation hints" toggle is a support-level cue that looks the same for right and wrong work; changing it on DOLs is a support-policy (IEP lane) decision.
- A teacher-authored test point's boundary questions are authored content graded against the truth.
- Inverse & Composition's inverse graph is an authored display that never reacts to the student's work.
- The legacy stepAlgebra2 intercepts mini-solver is unreachable: stored records migrate to the orchestrator, and the host-parity journey passes.
- On a DOL the student app sends no intercept step (B-24). A hand-crafted, authenticated step request is still credited by the server only when the intercept is right, so it could confirm an intercept before Submit. That is no new exposure. The browser already holds the question's line and the intercept check, because it renders and grades the tool, so a student able to craft such a request could run the check directly. Secure assessments never take this path: ingestion refuses them (`secure-assignment-excluded`). Making the server refuse the step on a DOL would not take that information away.

**I-9. A 1366×640 Chromebook window opens a marking step with 254 of the plane's 400 px on screen** (the x-axis one scroll below; measured by the repaired staged-question audit, B-33). The plane keeps its cap (the smaller of 70% of the window and the window less 240 px), but on this question the pinned task card (it carries the data table), the step heading and the action bar take about 385 px. Showing the whole plane on arrival means either a plane of about 250 px or unpinning the task card on short windows. #407 pinned that card so the task stays in view while the student works. Choosing between plane size and an always-visible task is a product decision. The audit prints the measurement on every run, so the choice can be made with the numbers.

**I-10. Limits of the draft precedence (B-46), all no worse than before.** A composed question is one record, so the newest edit to any of its steps wins the whole record. If a student works on two Chromebooks and one of them is offline, the other device's newer answers to other steps can be lost when it reconnects (before this PR, merely opening the question could do the same). Whether a write is the student's edit is inferred from real keyboard, pointer or input events since the draft was read: a double-click landing between a step's commit and its effects can count as one. An older build that saves a document drops the new marker from every entry in it, so those entries count as legacy until the next edit. All three are written up in the PQ-044 entry of `docs/qa/platform-quirks-audit.md`.

**I-11. The Live Challenge shell QA's `reconnect` scenario races itself (not this PR's; a protected lane).** `answerInBrowser` returns as soon as "Lock In Answer" is clicked, and the scenario force-closes the round on the next line. When the student's answer reaches the server second, `submitLiveChallengeResponse` refuses it, correctly ("That Live Challenge round is no longer active"). The QA's callable bridge answers 400, Chrome logs "Failed to load resource … 400", and the scenario's console check fails while every functional check passes. It was traced with a logging copy of the QA (never committed) and reproduces unchanged on `main` at `b45dc60b`: 2 of 4 runs there, 3 of 9 on this head, one run on each side with two CPU cores kept busy. `tests/browser/liveChallengeShellQa.mjs` is #413's Live Challenge QA, a lane this PR leaves unchanged. The fix belongs there and is test-only: before the force-close, wait until the harness's `bridgeCalls` holds that student's `submitLiveChallengeResponse`.
