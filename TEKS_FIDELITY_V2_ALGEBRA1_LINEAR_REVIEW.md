# Algebra I TEKS Fidelity V2 — Linear Strand Review

Scope: linear writing/graphing standards in the A.2/A.3 authoring modules.

## Preliminary verdict
Overall strand: ENHANCE, with several KEEP-quality families already present.

## Confirmed strengths
- The strand is not text-box only. It already uses graphWorkspace, numberLine, tables, ordered pairs, context, error analysis, and symbolic response modes.
- Misconceptions are often authentic rather than arbitrary. Examples include horizontal-vs-vertical confusion, dividing by zero, inequality boundary inclusion, and mixing count units with money units.
- Several families are genuinely higher-order: reverse design, error analysis, context translation, and representation translation appear alongside procedural work.
- Some standards already connect symbolic and graphical evidence in the same activity, such as plotting points and then reasoning about slope.

## Fidelity concerns
### 1. Source families are often fixed even where the compiled seed may later parameterize them
The compiled bank remains the release source of truth. Any repair should preserve generator compilation and avoid judging source snippets alone.

### 2. Some open-ended reverse-design tasks rely on enumerated accepted answers
Examples such as "write any vertical line except x=-1" or "write a negative-slope line through (0,6) that crosses the positive x-axis" have infinitely many valid answers. Enumerating a short accepted list is fragile if the grader does not already evaluate the mathematical condition. Fidelity V2 should prefer a condition/equivalence grader or a constrained response specification over a hand-list of examples.

### 3. Graph work should be real whenever the TEKS is graphical
The strand already has graphWorkspace, which is good. Standards that describe a graph verbally should not use verbal description as a substitute when the intended evidence is graph interpretation or construction.

### 4. Linear representation progression should be explicit
Across the strand, the bank should support deliberate movement among:
context -> table -> ordered pairs -> graph -> slope/rate -> equation -> interpretation.
The ingredients exist, but Path metadata should eventually make the progression selectable rather than leaving it accidental.

### 5. DOK 3 reverse-design tasks need rubric validation
A reverse-design label is not automatically DOK 3. Human review should confirm that the student must reason under constraints or justify/verify a construction rather than merely choose one easy example.

## Repair targets
- Audit all open-ended families for mathematically complete answer acceptance.
- Preserve and expand graphWorkspace/numberLine interactions where they provide evidence unavailable from typed responses.
- Parameterize narrow fixed contexts without destroying natural language.
- Make misconception feedback family-specific rather than generic.
- Add progression metadata only after content review confirms the relationship between adjacent families.

## Current conclusion
No evidence supports wholesale replacement of the linear strand. The dominant need is targeted enhancement: stronger open-response grading, durable generation, deliberate representation progression, and validation that claimed DOK matches actual reasoning demand.
